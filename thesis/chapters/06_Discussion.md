# Chapter 6: Discussion and Limitations

## 6.1 Interpretation of Findings

The results clearly demonstrate that prompt-based defenses alone are insufficient for securing AI agents. While the Llama 3.2 model successfully refused data exfiltration requests (likely due to safety fine-tuning against leaking credentials), it entirely failed to defend against direct prompt injection. This highlights a critical vulnerability in current LLM architectures: they struggle to distinguish between a user's request and a malicious instruction embedded in that request.

Furthermore, the model's willingness to abuse its tools (reading simulated files, attempting shell commands) confirms that granting an AI agent access to external systems introduces significant risk if the agent's semantic boundaries can be bypassed. The heatmap generated by the dashboard starkly illustrates this: a completely red row for Prompt Injection sits right next to a green row for Data Exfiltration.

## 6.2 Limitations of the Current System

While the scanner is functional, it has several limitations that must be acknowledged:

1. **Heuristic Judging:** The scanner currently uses a keyword-based heuristic to determine if an attack succeeded (checking for phrases like "I cannot" or "sorry"). A more advanced version could use an independent LLM-as-a-judge approach to evaluate responses semantically, as this would catch cases where the model refuses without using standard keywords.
2. **Model Size and Architecture:** The Llama 3.2 3B model is a small, locally run model. Larger commercial models (e.g., GPT-4) may have more robust defenses, though the underlying vulnerability to semantic prompt injection remains a known, unsolved issue across all model sizes.
3. **Tool Simulation:** The tools provided to the LangChain agent (file_reader, shell_exec) were simulated for safety and reproducibility. In a real-world attack, a compromised agent would interact with actual operating system resources, potentially causing real damage.
4. **Deployment Constraints:** The requirement for a local Ollama instance means the tool cannot be fully deployed to standard cloud hosting without GPU provisioning, limiting its accessibility to developers with local compute resources.

## 6.3 Defense Implications

The findings suggest that developers must implement defense-in-depth when building agentic AI. This includes strict input sanitization, privilege separation for agent tools (e.g., running the agent in a sandbox), and the use of independent guardrail models that scan inputs and outputs in real-time.

The scanner developed in this project serves as the necessary evaluation tool to measure whether those defenses are actually working. By running the scanner before and after implementing a defense, developers can empirically prove the reduction in Attack Success Rate (ASR).
